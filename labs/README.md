
# GraySentinel Cybersecurity Labs

**Proof Over Certificates | Practical Security Skills | Verifiable Evidence**

Welcome to the GraySentinel Cybersecurity Labs.

This repository contains practical cybersecurity exercises designed to help learners develop, demonstrate and validate real-world security capabilities.

Our approach is simple:

**Learn → Practise → Investigate → Document → Prove**

We focus on practical execution rather than certificate collection.

---

## 1. About the Labs

GraySentinel Labs provide structured, hands-on cybersecurity exercises across multiple security domains.

Each lab is designed to help learners:

- Understand real-world security scenarios.
- Work with cybersecurity tools and technologies.
- Analyse security events and identify weaknesses.
- Develop technical problem-solving skills.
- Document findings and investigation processes.
- Produce verifiable evidence of practical capability.

These labs are intended for students, aspiring cybersecurity professionals, security practitioners and independent researchers.

## 3. How the Lab System Works

Every lab follows a structured execution workflow.

1. **Scenario:** Understand the security problem.
2. **Objective:** Identify what needs to be accomplished.
3. **Environment:** Prepare the required tools and datasets.
4. **Execution:** Perform the practical activity.
5. **Analysis:** Interpret the results and findings.
6. **Evidence:** Capture relevant outputs and supporting artifacts.
7. **Documentation:** Explain the methodology and conclusions.
8. **Review:** Evaluate the quality and correctness of the work.

## 7. Evidence and Proof of Work

GraySentinel evaluates practical execution through verifiable evidence.

Acceptable evidence may include:

- Screenshots of relevant tool outputs.
- Configuration files.
- Detection rules and SIEM queries.
- Scripts and source code.
- Packet captures from authorized lab environments.
- Log analysis results.
- Investigation reports.
- Documented findings and remediation recommendations.

### Evidence Quality Standards

Every submission should be:

1. Relevant to the assigned objective.
2. Genuine and produced by the learner.
3. Technically understandable.
4. Reproducible wherever practical.
5. Properly documented.
6. Free from unauthorized sensitive information.

Screenshots alone are not sufficient proof of technical capability.

## 9. Rules and Responsible Use

All activities must be conducted legally and ethically.

### Mandatory Rules

- Use only authorized systems and environments.
- Never target public systems without permission.
- Do not access or expose another person's data.
- Do not distribute malicious software.
- Do not attempt unauthorized account access.
- Do not publish passwords, tokens, private keys or personal information.
- Follow the scope and restrictions of every exercise.

Violations may result in rejection of submitted work or removal from the learning environment.

## 10. Getting Started

If you are new to cybersecurity:

1. Begin with Module 01: Networking.
2. Follow the corresponding practical exercises.
3. Complete each assigned task.
4. Maintain a GitHub repository of your work.
5. Document your methodology and findings.
6. Progress to more advanced exercises.

If you already have relevant experience, review the module objectives and select exercises appropriate to your current capabilities.

# GraySentinel SOC Analyst Roadmap

**Security Skills. Shown, Not Claimed.**

A practical, evidence-first cybersecurity learning roadmap designed to help aspiring Security Operations Centre (SOC) Analysts develop, demonstrate and validate defensive security capabilities.

Learn cybersecurity foundations, analyse security events, investigate suspicious activity, understand defensive security controls, develop detection rules and build a portfolio backed by verifiable evidence.

**Learning Philosophy: Proof Over Certificates.**

---

## 1. About This Repository

The GraySentinel SOC Analyst Roadmap is an open educational resource developed by GraySentinel Cyber Defence Lab.

It provides a structured learning path covering essential cybersecurity concepts and practical defensive security skills.

This repository focuses on:

- Understanding networking and operating systems.
- Learning essential cybersecurity principles.
- Analysing security logs and system events.
- Understanding network and endpoint security.
- Learning identity and access management.
- Developing security detection rules.
- Practising through structured cybersecurity labs.
- Building a verifiable technical portfolio.

Our learning approach:

**Mission → Execute → Evidence → Artifact → Review → Portfolio**

## 4. Portfolio and Proof of Work

GraySentinel believes cybersecurity capability should be demonstrated through actual technical work.

Learners should progressively build a portfolio containing:

- Technical investigation reports.
- Sanitized security logs.
- Packet analysis findings.
- Detection rules and SIEM queries.
- Scripts and configuration files.
- Incident timelines.
- Testing results.
- Documented findings and recommendations.

### Portfolio Quality Standards

Every submission should demonstrate:

1. What was investigated or developed.
2. Why the activity was performed.
3. How the work was executed.
4. What evidence was generated.
5. What the results demonstrate.
6. What limitations or uncertainties remain.

Screenshots without technical explanations are not sufficient proof of capability.

## 9. Responsible Learning

All cybersecurity activities must be performed ethically and legally.

- Use only systems you own or have explicit authorization to assess.
- Perform testing in controlled environments.
- Never access or expose unauthorized information.
- Do not publish credentials, API keys or private data.
- Follow the scope and restrictions of each exercise.
- Report discovered vulnerabilities responsibly.

Read our [Security Policy](./SECURITY.md) for reporting guidance.

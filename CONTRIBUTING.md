# Contributing

Suitable contributions include correcting technical errors with authoritative references, improving explanations, adding safe reproducible labs, adding synthetic datasets, improving assessments and fixing broken links.

Before opening a pull request:
1. Read the relevant module and avoid duplication.
2. Explain the learning objective and intended audience.
3. Include prerequisites, steps, expected output and cleanup instructions for labs.
4. Cite authoritative sources and respect their licences.
5. Remove credentials, tokens, personal information and confidential data.
6. Test commands in an isolated, authorised environment.
7. State known limitations and version assumptions.

Submissions are reviewed for accuracy, safety, clarity, reproducibility, originality and attribution. A pull request is not accepted until an authorised maintainer approves and merges it.

Recognition is based on accepted work and the applicable GOCP policy. Opening a pull request does not guarantee points, a badge, a certificate, an internship or paid work.

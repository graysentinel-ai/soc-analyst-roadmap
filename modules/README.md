## 2. Recommended Learning Sequence

Follow the modules in order if you are beginning your cybersecurity journey.

### Stage 1: Technical Foundations

**Module 01: Networking Foundations**

Understand how computers communicate, how network protocols operate and how to interpret network traffic.

**Module 02: Operating Systems**

Learn Linux and Windows fundamentals, including processes, services, permissions, users and system events.

### Stage 2: Security Knowledge

**Module 03: Security Fundamentals**

Understand security principles, common threats, vulnerabilities, attack concepts and defensive practices.

**Module 04: Log Analysis**

Learn how to read security logs, investigate authentication events, identify unusual activity and construct event timelines.

### Stage 3: Defensive Security

**Module 05: Network Security**

Understand firewalls, network segmentation, packet inspection, network monitoring and defensive controls.

**Module 06: Endpoint Security**

Learn endpoint monitoring, process investigation, endpoint protection and suspicious system activity analysis.

### Stage 4: Access and Detection

**Module 07: Identity & Access Management**

Understand identity lifecycle, authentication, authorization, permissions, privileged access and access reviews.

**Module 08: Detection Engineering**

Learn to develop, test and improve security detections using Sigma rules, SIEM queries, security telemetry and MITRE ATT&CK mapping.

## 3. What Each Module Should Contain

Every module should follow a consistent educational and practical structure.

| Section | Purpose |
|---|---|
| Overview | Introduce the subject and its importance |
| Learning Objectives | Explain expected knowledge and capabilities |
| Prerequisites | Identify required background knowledge |
| Core Concepts | Explain important technical topics |
| Practical Exercises | Provide hands-on learning activities |
| Tools and Technologies | Introduce relevant tools |
| Evidence Requirements | Define what learners must document |
| Assessment | Evaluate conceptual understanding |
| Further Learning | Provide official references and next steps |

Content should be determined by the learning objectives, not arbitrary page counts.

---

## 4. Practical Learning Standards

Theory must connect to practical execution.

Every practical exercise should clearly explain:

1. What is the objective?
2. Why is the exercise important?
3. What environment is required?
4. Which tools and datasets are needed?
5. What steps should the learner perform?
6. What results should be expected?
7. What evidence should be documented?
8. How will the work be evaluated?

Exercises should use authorized, isolated or synthetic environments.

Never use real customer data, exposed credentials or unauthorized systems.

---

## 5. Evidence and Portfolio Expectations

GraySentinel emphasizes demonstrable practical capability.

Learners should maintain evidence of their work, including:

- Technical notes and explanations.
- Sanitized log analysis.
- Packet analysis worksheets.
- Network investigation findings.
- Endpoint investigation reports.
- Configuration files and scripts.
- SIEM queries and detection rules.
- Testing results and screenshots.
- Incident timelines and technical reports.
- Documented limitations and recommendations.

### Evidence Quality Standards

Every submission should be:

- Genuine and produced by the learner.
- Relevant to the assigned objective.
- Technically understandable.
- Reproducible wherever practical.
- Properly documented.
- Free from unauthorized sensitive information.

A screenshot without supporting context is not sufficient to establish practical capability.

## 6. Module Completion Standards

A module should be considered completed by a learner only after they have:

1. Reviewed the learning objectives.
2. Studied the relevant concepts.
3. Completed the required practical activities.
4. Documented the required evidence.
5. Completed the applicable assessment.
6. Reviewed feedback and corrected identified gaps.

Reading documentation alone does not establish practical competency.

## 9. Responsible Learning and Security

All practical activities must follow responsible security practices.

- Work only on systems you own or have explicit authorization to assess.
- Use isolated lab environments where possible.
- Never expose passwords, API keys or private information.
- Do not conduct unauthorized vulnerability testing.
- Follow the scope and restrictions of each exercise.
- Report discovered security issues responsibly.

Read the repository's [Security Policy](../SECURITY.md) for reporting guidance.


# SOC Analyst Learning Modules

Welcome to the GraySentinel SOC Analyst learning modules.

This directory contains the structured learning material for developing practical defensive cybersecurity and Security Operations Centre (SOC) skills.

The learning sequence moves from foundational technical knowledge to security investigation, SIEM operations, incident response and detection engineering.

**Learning principle: Understand → Practise → Document → Validate.**

# 2. Recommended Learning Order

Follow the modules in sequence if you are new to defensive cybersecurity.

## Stage 1: Technical Foundations

**Module 01: Networking Foundations**

Understand how systems communicate, how network protocols work and how to interpret basic network traffic.

**Module 02: Operating Systems**

Understand Linux and Windows environments, processes, services, users and system events.

## Stage 2: Security Knowledge

**Module 03: Security Fundamentals**

Learn essential security concepts, common threats, indicators and defensive security principles.

**Module 04: Log Analysis**

Learn how to interpret event records, investigate authentication activity and build event timelines.

## Stage 3: SOC Practice

**Module 05: SOC Operations**

Understand alert monitoring, investigation workflows, prioritisation and escalation.

**Module 06: SIEM Fundamentals**

Learn how security monitoring platforms collect, search, correlate and present security events.

## Stage 4: Investigation and Detection

**Module 07: Incident Response**

Understand incident investigation, evidence handling, timelines and reporting.

**Module 08: Detection Engineering**

Learn how to develop, test and improve defensive detection rules.

# 3. What Each Module Should Contain

Each module should follow a consistent documentation structure.

| Section | Purpose |
|---|---|
| Overview | Introduce the module |
| Learning Objectives | Explain what the learner should understand |
| Prerequisites | Identify required background knowledge |
| Concepts | Explain important technical topics |
| Practical Exercises | Provide hands-on learning activities |
| Tools and Resources | Identify relevant tools and references |
| Evidence Requirements | Explain what learners must document |
| Assessment | Check understanding and practical ability |
| Further Learning | Provide next steps and references |

Not every module requires the same number of exercises. Content should be determined by the learning objectives rather than an arbitrary page count.

---

# 4. Practical Learning Standards

Every practical exercise should make the following clear:

1. What is the objective?
2. Why is the exercise important?
3. What environment is required?
4. What steps should the learner follow?
5. What result should the learner expect?
6. What evidence should be documented?
7. How will the result be evaluated?

Exercises should use authorised, isolated or synthetic environments.

Do not use real customer data, exposed credentials or unauthorised systems.

---

# 5. Evidence and Portfolio Expectations

Learners should maintain evidence of their practical work.

Examples include:

- Technical notes.
- Sanitised log analysis.
- Packet analysis worksheets.
- Investigation timelines.
- SIEM search queries.
- Dashboard screenshots.
- Detection rules.
- Test results.
- Incident reports.

Evidence must be genuine, relevant and supported by an explanation of the work performed.

A screenshot without context is not sufficient to demonstrate technical understanding.

---

# 6. Module Completion

A module should be considered complete only after the learner has:

- Reviewed the learning objectives.
- Studied the relevant concepts.
- Completed the required practical exercises.
- Documented the expected evidence.
- Completed the applicable assessment.
- Reviewed feedback and corrected identified gaps.

Reading a module or watching a demonstration alone does not establish practical competency.

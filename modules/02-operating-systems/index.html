Module Overview

An operating system manages a computer's hardware, applications, files, users and system resources. It provides the environment in which software runs and system activity is recorded.

For a SOC Analyst, operating system knowledge is essential. Security investigations often involve understanding login events, running processes, service activity, account changes and system logs.

Why does a SOC Analyst need operating system knowledge? When an alert reports unusual activity, an analyst may need to identify the affected user, inspect a process, understand a service, review authentication records and determine what happened on the endpoint.

Topic 01

Operating System Fundamentals

An operating system is system software that manages hardware resources and provides services to applications.

Major Operating System Responsibilities

Process Management

Manages running programs and their execution.

Memory Management

Allocates and manages system memory.

File Management

Organises files, directories and storage access.

User Management

Manages accounts, identities and permissions.

Device Management

Coordinates hardware devices and drivers.

Security Management

Supports authentication, access control and security auditing.

Common Operating Systems

Operating System Common Use
Windows Personal computers, enterprise endpoints and servers.
Linux Servers, cloud infrastructure, workstations and security labs.
macOS Apple desktop and laptop systems.
Unix-like systems Servers, infrastructure and specialised computing environments.
SOC perspective Different operating systems produce different logs and expose different investigation tools. An analyst must understand the environment before interpreting its events.
Topic 02

Linux Fundamentals

Linux is an open-source operating system kernel used in many server, cloud, embedded and workstation environments. Linux distributions combine the kernel with other software to provide a complete operating system.

Common Linux Distributions

  • Ubuntu.
  • Debian.
  • Fedora.
  • Red Hat Enterprise Linux.
  • Rocky Linux.
  • AlmaLinux.

Linux Filesystem Structure

Linux organises files and directories under a single directory tree that begins at the root directory.

Directory Purpose
/ Root of the filesystem.
/home Home directories for regular users.
/root Home directory of the root account.
/etc System-wide configuration files.
/var Variable data such as logs and application data.
/var/log Common location for system and application logs.
/tmp Temporary files.
/usr Many user-space programs, libraries and shared resources.
/bin Essential command binaries on systems using this layout.
/dev Device files.

Essential Linux Commands

Command Purpose Example
pwd Show current directory. pwd
ls List directory contents. ls -la
cd Change directory. cd /var/log
cat Display file contents. cat file.txt
less Read long files interactively. less file.txt
grep Search text patterns. grep "error" file.log
find Search for files and directories. find /var/log -name "*.log"
whoami Show current user identity. whoami
id Show user and group identifiers. id
ps Display process information. ps aux
top Monitor running processes. top
df Show filesystem space usage. df -h

Understanding Command Output

For example, consider:

whoami

This command displays the username associated with the current shell session.

Another example:

ps aux

This displays process information, including users, process identifiers and resource usage.

Analyst habit Never interpret a command result without understanding which user executed it, which system it ran on and when the observation was collected.
Topic 03

Linux Users and Permissions

Linux uses user and group identities to control access to files, directories and system resources.

Important Concepts

  • Root: The administrative superuser account.
  • Regular User: An account used for normal system activity.
  • Group: A collection of users used for access management.
  • UID: Numeric user identifier.
  • GID: Numeric group identifier.
  • sudo: A mechanism for executing permitted commands with elevated privileges.

File Permissions

Linux file permissions commonly distinguish three classes:

Class Meaning
u Owner or user.
g Group.
o Others.

Permission Types

Permission Symbol Numeric Value
Read r 4
Write w 2
Execute x 1

Example Permission

-rwxr-xr--

This represents:

  • Owner: read, write and execute.
  • Group: read and execute.
  • Others: read only.

Useful Commands

whoami id groups ls -l chmod 640 file.txt chown user:group file.txt
Permission safety Do not change permissions on system files while learning. Use a test directory and files you own. Commands such as chmod and chown can affect system security and availability.

Understanding sudo

The sudo command allows an authorised user to execute a command with elevated privileges according to the system's sudo policy.

sudo command

Elevated privileges should be used only when necessary and within an authorised environment.

Topic 04

Windows Fundamentals

Windows is widely used in enterprise environments. SOC Analysts frequently investigate Windows endpoints, servers, authentication activity, processes and security events.

Important Windows Components

File Explorer

Navigate files, directories and storage locations.

Task Manager

Inspect processes, performance and running applications.

Services

Manage background services running on the system.

Event Viewer

Inspect recorded system, application and security events.

Windows Defender

Explore built-in security and threat protection features.

PowerShell

Use a command-line shell and scripting environment for administration.

Important Windows Directories

Location Purpose
C:\Windows Windows operating system files.
C:\Windows\System32 Important system binaries and components.
C:\Users User profile directories.
C:\Program Files Common location for installed applications.
C:\ProgramData Application data shared across users.
C:\Windows\System32\winevt\Logs Common location for Windows event log files.

Windows Command Line

Useful Command Prompt commands:

whoami hostname systeminfo ipconfig /all tasklist netstat -ano dir cd type

PowerShell Fundamentals

PowerShell provides commands known as cmdlets for interacting with Windows and other supported systems.

Get-ComputerInfo Get-Process Get-Service Get-ChildItem Get-Date Get-EventLog -LogName System -Newest 10

PowerShell commands and available parameters may differ between Windows PowerShell and PowerShell versions. Verify the documentation for the environment you use.

SOC perspective Understanding Task Manager, PowerShell and Windows administrative tools helps analysts investigate endpoint activity and interpret security alerts.
Topic 05

Windows Accounts and Access Control

Windows uses security identities and access control mechanisms to determine what users and processes are permitted to do.

Common Account Types

Account Type Description
Standard User Performs ordinary activities with limited permissions.
Administrator Has elevated administrative permissions.
Local Account Account managed on an individual Windows system.
Domain Account Account managed through an organisational identity environment.
Service Account Identity used by a service or application.

Useful Commands

whoami whoami /groups whoami /priv net user net localgroup

These commands can provide information about the current identity, group memberships, privileges and local accounts.

Access Control Concepts

  • Authentication: Verifying an identity.
  • Authorisation: Determining permitted actions.
  • Least Privilege: Providing only the access needed for a task.
  • Security Identifier: A Windows identifier used to represent security principals.
  • Access Control List: Rules describing access permissions for an object.
Investigation example If an alert indicates an unexpected account change, an analyst may review account management events, group membership and relevant administrative activity.
Topic 06

Processes and Process Investigation

A process is a running instance of a program. Operating systems manage processes and allocate resources such as CPU time and memory.

Important Process Information

  • Process name.
  • Process identifier (PID).
  • Parent process identifier (PPID), where available.
  • Process owner or security context.
  • Executable path.
  • Command-line arguments, where available.
  • Resource usage.
  • Start time and execution context, where available.

Linux Process Commands

ps aux top pgrep process_name pstree pidof process_name

Windows Process Commands

tasklist Get-Process Get-CimInstance Win32_Process

Parent and Child Processes

A parent process may create one or more child processes. Understanding process relationships can help analysts reconstruct execution activity.

Parent Process | +-- Child Process A | +-- Child Process B | +-- Child Process C

What Should an Analyst Examine?

  • Is the process expected on this system?
  • Does the executable path make sense?
  • Which user or security context launched it?
  • What is its parent process?
  • Are the command-line arguments expected?
  • Is there supporting evidence of suspicious activity?
Important A familiar process name does not prove that a process is legitimate. Likewise, an unfamiliar process name does not automatically indicate malware. Examine multiple evidence sources before drawing conclusions.
Topic 07

Operating System Services

Services are background components that provide functionality to an operating system or applications.

Linux Services

Many Linux distributions use systemd to manage system services.

systemctl status service_name systemctl list-units --type=service systemctl is-active service_name systemctl is-enabled service_name

These commands help inspect service status, active units and startup configuration.

Windows Services

Windows services run in the background and may start automatically, manually or through other configured startup triggers.

Get-Service Get-Service -Name "Spooler" sc query

What Should a SOC Analyst Check?

  • Service name and description.
  • Current status.
  • Startup configuration.
  • Associated executable or service process.
  • Service account or execution identity.
  • Recent configuration or state changes.
Security investigation example An unexpected service may require investigation. Check its configuration, executable location, associated account and creation or modification events before deciding whether it is suspicious.
Topic 08

Operating System Logs

Operating systems record events that describe system activity. These records can support troubleshooting, auditing and security investigations.

Linux Logs

Many Linux systems store log files under /var/log. Exact locations and log formats depend on the distribution and configuration.

Log Source Typical Purpose
/var/log/auth.log Authentication-related activity on systems using this log file.
/var/log/secure Authentication and security-related activity on systems using this log file.
/var/log/syslog General system messages on systems using this log file.
/var/log/messages General system messages on systems using this log file.
systemd journal Structured system and service logs on systemd-based systems.

Useful Linux Log Commands

ls -lah /var/log journalctl journalctl -b journalctl -u service_name journalctl --since "1 hour ago" grep "failed" /var/log/auth.log

The last example assumes the system uses /var/log/auth.log and that the user has permission to read it.

Windows Event Viewer

Windows Event Viewer is a built-in tool used to inspect recorded events.

Common event log categories include:

Log Purpose
Application Events generated by applications.
System Events generated by Windows system components.
Security Audited security activity, depending on audit configuration.
Setup Installation and setup-related events.

Useful Windows Security Event IDs

Event ID Meaning
4624 An account was successfully logged on.
4625 An account failed to log on.
4634 An account was logged off.
4648 A logon was attempted using explicit credentials.
4720 A user account was created.
4722 A user account was enabled.
4724 An attempt was made to reset an account password.
4732 A member was added to a security-enabled local group.
Event interpretation matters Event IDs are useful references, but their meaning depends on the event details, audit configuration, system role and surrounding activity. A failed login is not automatically evidence of an attack.

Example: Inspect Windows Events with PowerShell

Get-WinEvent -LogName Security -MaxEvents 10 Get-WinEvent -FilterHashtable @{ LogName = 'Security' Id = 4625 } -MaxEvents 10

The second example searches for recent failed logon events in the local Security log. Access permissions and audit configuration affect the available results.

1. Learning objectives

By the end of this module, you should be able to:

  • Explain basic network communication and common network components.
  • Understand the OSI and TCP/IP models at a practical level.
  • Identify common protocols, ports and their purposes.
  • Explain how firewalls, segmentation and secure protocols reduce risk.
  • Interpret basic network connection and DNS records.
  • Recognise traffic patterns that deserve further investigation.
  • Document network observations with supporting evidence.
Defender's mindset: Network security is not simply blocking everything unfamiliar. It is understanding what should communicate, why it should communicate, and whether the observed activity matches the approved design.

2. Network fundamentals

A computer network connects devices so they can exchange information. Communication uses agreed rules called protocols. Security teams monitor and control this communication to reduce unauthorised access, data exposure and service disruption.

IP address

A logical address used to identify an interface on an IP network.

MAC address

A link-layer address associated with a network interface.

Router

Forwards packets between different networks.

Switch

Connects devices within a local network, commonly using MAC addresses.

DNS

Resolves domain names into records such as IP addresses.

DHCP

Automatically provides network configuration to clients.

Gateway

The next-hop device used to reach networks outside the local subnet.

Subnet

A defined IP network range used to organise and route addresses.

Private IPv4 address ranges

3. OSI and TCP/IP models

Network models help describe where communication functions happen. The OSI model has seven conceptual layers. The TCP/IP model groups networking functions into a smaller set of layers.

OSI layerFunctionExamples
7. ApplicationApplication-level network servicesHTTP, DNS, SMTP
6. PresentationData representation and encryption conceptsEncoding, TLS-related functions
5. SessionSession establishment and management conceptsSession coordination
4. TransportEnd-to-end transportTCP, UDP
3. NetworkLogical addressing and routingIPv4, IPv6, ICMP
2. Data LinkLocal network frame deliveryEthernet, Wi-Fi MAC
1. PhysicalTransmission of raw bitsCables, radio signals

TCP/IP model overview

Application

Application protocols such as HTTP, DNS, SMTP and SSH.

Transport

TCP and UDP communication between endpoints.

Internet

IP addressing, packet forwarding and routing.

Network Access

Local network communication and physical transmission.

Models are learning tools. Real protocols and implementations do not always fit perfectly into one simplified layer.

4. Common protocols and ports

A port identifies an application endpoint on a transport-layer connection. A familiar port number can suggest a service, but it does not prove which application is actually running.

Protocol / ServiceCommon portPurposeSecurity consideration
HTTPTCP 80Web trafficUnencrypted application traffic
HTTPSTCP 443Protected web trafficValidate TLS configuration and certificates
SSHTCP 22Secure remote administrationRestrict access and use strong authentication
DNSUDP/TCP 53Name resolutionMonitor unusual queries and unexpected resolvers
SMTPTCP 25Mail transferRestrict relaying and protect mail infrastructure
SMBTCP 445Windows file and printer sharingLimit exposure and enforce access controls
RDPTCP/UDP 3389Remote desktop accessRestrict exposure and require strong authentication
NTPUDP 123Time synchronisationUse trusted time sources
DHCPUDP 67/68Dynamic address configurationProtect against unauthorised DHCP services
SNMPUDP 161/162Network monitoring and managementUse secure versions and restrict management access
A port being open is not automatically a vulnerability. Investigate whether the service is expected, exposed appropriately, configured securely and required for the asset's role.

5. Network security controls

Firewall

Applies rules to allow, deny or inspect network traffic.

Network segmentation

Separates systems into controlled network zones.

IDS

Detects activity that matches known or configured suspicious patterns.

IPS

Can actively block or prevent selected suspicious traffic.

VPN

Provides an encrypted tunnel across an underlying network.

Network Access Control

Applies access decisions based on device or user policy.

Firewall rule components

A firewall policy may consider:

  • Source address or network.
  • Destination address or network.
  • Protocol, such as TCP, UDP or ICMP.
  • Source and destination ports.
  • Direction and network interface.
  • Action, such as allow, deny or log.

Example policy

Rule 1:
Source: 10.10.10.0/24
Destination: 10.10.20.10
Protocol: TCP
Destination port: 443
Action: ALLOW
Purpose: Approved application access

Rule 2:
Source: ANY
Destination: 10.10.20.10
Protocol: ANY
Action: DENY
Purpose: Deny other unapproved traffic

This is an illustrative policy, not a production-ready firewall configuration. Real rule ordering, state handling, return traffic, management access and change approvals must be considered.

Principles of secure network design

  • Allow only required communication.
  • Separate user, server, management and sensitive environments.
  • Restrict administrative access to approved management paths.
  • Use secure protocols and appropriate encryption.
  • Log important network decisions and review them.
  • Review firewall rules periodically and remove obsolete access.

6. Network traffic analysis

Network traffic analysis examines communication records or packet captures to understand what devices are communicating, which protocols they use and whether the activity is expected.

What is a packet?

A packet is a formatted unit of data carried across a network. Packet headers contain information used for delivery, such as source and destination addresses. The exact fields depend on the protocol.

Connection metadata to review

FieldInvestigation question
Source IPWhich device initiated or sent the traffic?
Destination IPWhich system received the traffic?
Source portWhich source endpoint port was used?
Destination portWhich destination service may be involved?
ProtocolWas the communication TCP, UDP, ICMP or another protocol?
Bytes / packetsHow much data or how many packets were observed?
DurationHow long did the observed connection last?
DirectionWas the traffic inbound, outbound or internal?

TCP connection basics

TCP commonly establishes a connection using a three-way handshake: 

Client                 Server
  |                       |
  |------ SYN ----------->|
  |                       |
  |<----- SYN-ACK --------|
  |                       |
  |------ ACK ----------->|
  |                       |
  |   Connection ready    |

Repeated connection attempts, incomplete handshakes or unexpected connection patterns may deserve investigation. They can also occur because of normal application behaviour, network errors or scanning.

Packet capture and inspection

  • Capture only traffic you are authorised to inspect.
  • Choose a clear interface, time range and capture filter.
  • Protect packet captures because they may contain sensitive information.
  • Use display filters to focus on relevant protocols or endpoints.
  • Preserve the original capture and document analysis steps.
Encrypted traffic may reveal useful metadata while keeping application content unreadable. Do not assume that a packet capture exposes the contents of a properly encrypted session.

Example commands

These are basic inspection commands for systems you own or are authorised to administer.

# Display IP configuration
ip addr

# Display routing information
ip route

# Check DNS resolution
nslookup example.com

# Display listening TCP and UDP sockets
ss -tuln

# Display active TCP connections
ss -tn

# Capture traffic on an authorised interface
sudo tcpdump -i eth0

# Capture DNS traffic for analysis
sudo tcpdump -i eth0 port 53
Packet capture can expose credentials, personal information and confidential communications. Follow organisational policy and obtain explicit authorisation before capturing traffic.

11. Network investigation report

Use a repeatable report structure so another analyst can reproduce your reasoning.

  1. Investigation question: What activity are you checking?
  2. Authorisation and scope: Which systems and networks are in scope?
  3. Data sources: Firewall, DNS, packet capture, endpoint or other records.
  4. Time context: Time range, time zone and clock considerations.
  5. Method: Filters, queries, tools and analysis steps.
  6. Observations: What the available records directly show.
  7. Assessment: What the observations may indicate and confidence level.
  8. Limitations: Missing data, encryption or incomplete visibility.
  9. Recommendations: Specific authorised next steps.
  10. Evidence references: File names, hashes where appropriate and record references.

Example finding

Observation:
The synthetic firewall records show repeated outbound connection
attempts from workstation 10.10.10.25 to multiple destinations.

Assessment:
The activity deserves validation against the workstation's role
and approved application inventory. The records alone do not
establish malicious intent.

Next checks:
Review DNS queries, endpoint process telemetry, asset ownership,
firewall policy and the organisation's normal traffic baseline.

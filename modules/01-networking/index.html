Module Overview

Every device connected to a network communicates through defined rules and protocols. Security analysts study these communications to understand normal behaviour and identify suspicious activity.

Before investigating network attacks, you need to understand how networks operate. This module introduces the concepts that form the foundation of network security monitoring.

Why does a SOC Analyst need networking? Network logs and packet captures can reveal communication between devices, unusual connections, suspicious destinations, unexpected services and other activity that may require investigation.

Topic 01

Understanding Computer Networks

A computer network is a group of connected devices that communicate and exchange information.

These devices may include computers, servers, routers, switches, mobile devices and other network-connected systems.

Common Network Types

LAN · Local Area Network

Connects devices within a limited geographical area, such as a home, office or laboratory.

WAN · Wide Area Network

Connects networks across larger geographical distances.

WLAN · Wireless LAN

Connects devices through wireless networking technology, commonly Wi-Fi.

Internet

A global network of interconnected networks that communicate using common protocols.

Important Network Devices

Device Purpose
Router Forwards traffic between different networks.
Switch Connects devices within a local network.
Firewall Controls network traffic according to security rules.
Access Point Provides wireless network connectivity.
Server Provides services or resources to other systems.
SOC perspective An unexpected communication path or an unusual network service may provide an investigation lead. It does not, by itself, prove malicious activity.
Topic 02

IP Addressing

An Internet Protocol address identifies a network interface for communication using the IP protocol.

IPv4 Address

IPv4 addresses use 32 bits and are commonly written as four decimal numbers separated by dots.

192.168.1.10

Each decimal section represents eight bits and ranges from 0 to 255.

Private IPv4 Address Ranges

Private Range CIDR Address Range
10.0.0.0 /8 10.0.0.0 – 10.255.255.255
172.16.0.0 /12 172.16.0.0 – 172.31.255.255
192.168.0.0 /16 192.168.0.0 – 192.168.255.255

Public and Private IP Addresses

Private addresses are used within private networks and are not directly globally routable on the public internet. Public addresses are used for globally routable internet communication.

Other Important Addressing Concepts

  • Subnet Mask: Helps identify the network and host portions of an IPv4 address.
  • Default Gateway: Provides a route to other networks.
  • DNS: Resolves domain names to IP addresses.
  • MAC Address: Identifies a network interface at the data-link layer.
  • Loopback: IPv4 loopback traffic commonly uses 127.0.0.1.

Example Network Configuration

IP Address: 192.168.1.10 Subnet Mask: 255.255.255.0 Default Gateway: 192.168.1.1 DNS Server: 192.168.1.1

This is an illustrative private network configuration. Actual values depend on the network environment.

Topic 03

OSI and TCP/IP Models

Network models help explain how data moves through different networking functions.

The OSI Model

The OSI model contains seven layers.

Layer Name Function
7 Application Network services used by applications.
6 Presentation Data representation, encoding and encryption concepts.
5 Session Session establishment and management.
4 Transport End-to-end transport and port addressing.
3 Network Logical addressing and routing.
2 Data Link Local network framing and MAC addressing.
1 Physical Physical transmission of bits.

The TCP/IP Model

Layer Examples
Application HTTP, HTTPS, DNS, SMTP
Transport TCP, UDP
Internet IP, ICMP
Network Access Ethernet, Wi-Fi
Why this matters in security investigations Understanding network layers helps analysts reason about where an event occurs. For example, routing issues, transport connections and application requests describe different parts of network communication.
Topic 04

Common Network Protocols

A protocol defines rules that allow systems to exchange information.

Protocol Purpose Common Port
HTTP Web communication 80
HTTPS Encrypted web communication 443
DNS Domain name resolution 53
DHCP Automatic network configuration 67 / 68
SSH Secure remote administration 22
SMTP Email transmission 25
FTP File transfer 20 / 21
RDP Remote Desktop Protocol 3389
SNMP Network device monitoring and management 161 / 162
Important Common port numbers are conventions, not proof of the application or service running on a connection. Services can use non-standard ports, and port observations must be interpreted with additional evidence.

DNS: Domain Name System

DNS translates domain names into information used to locate network services, commonly including IP addresses.

For example:

example.com → Resolved IP address

During an investigation, DNS records can help analysts understand which domain names a system attempted to resolve.

DHCP: Dynamic Host Configuration Protocol

DHCP can automatically provide network configuration information such as IP addresses, subnet masks, gateways and DNS server information.

HTTP and HTTPS

HTTP is an application-layer protocol used for web communication. HTTPS uses HTTP over a protected TLS connection.

SSH

SSH provides encrypted remote access and administration. It is commonly used to manage Linux and other networked systems.

Topic 05

Ports and Services

An IP address identifies a network interface for IP communication. A transport-layer port helps identify the application or service endpoint.

TCP and UDP port numbers range from 0 to 65535.

Port Categories

Range Category
0–1023 Well-known ports
1024–49151 Registered ports
49152–65535 Dynamic or private ports

Example Connection

Source IP: 192.168.1.10 Source Port: 51524 Destination IP: 93.184.216.34 Destination Port: 443 Protocol: TCP

This example describes a TCP connection from a client using source port 51524 to a destination using port 443. The port alone does not establish what application content was exchanged.

SOC investigation question Is this connection expected for the system, user, time and business context? Analysts need supporting evidence before deciding whether an event is suspicious.
Topic 06

Understanding Network Traffic

Network traffic is the data exchanged between devices. Analysts may inspect traffic metadata, packet headers and permitted packet contents to understand communication.

What Is a Packet?

A packet is a unit of data transmitted across a network. Its structure depends on the protocols being used.

Important Packet Information

  • Source IP address.
  • Destination IP address.
  • Source port.
  • Destination port.
  • Transport protocol.
  • Packet length.
  • Timestamp.
  • Relevant protocol flags and fields.

TCP Fundamentals

TCP is a connection-oriented transport protocol. It provides mechanisms for reliable, ordered data delivery.

TCP Three-Way Handshake

01 · SYN Client requests a connection.
02 · SYN-ACK Server acknowledges and responds.
03 · ACK Client acknowledges the response.
04 · Established Data communication can begin.

UDP Fundamentals

UDP is a connectionless transport protocol. It does not establish a TCP-style connection before transmitting data.

UDP is commonly used where low overhead and application-level handling of delivery are important.

TCP vs UDP

TCP UDP
Connection-oriented Connectionless
Reliable, ordered delivery mechanisms No built-in guarantee of delivery or ordering
Uses connection state and acknowledgements Has lower protocol overhead
Commonly used for HTTPS and SSH Commonly used for DNS queries and real-time applications
Practical takeaway Do not classify traffic as malicious simply because it uses TCP, UDP or a particular port. Investigate the communication context and supporting evidence.
Hands-on Learning

Practical Exercises

Complete these exercises in your own computer or an authorised training environment. Use only systems and network traffic you are permitted to inspect.

Exercise 01

Inspect Your Network Configuration

Objective: Identify your device's network configuration.

Windows command:

ipconfig /all

Linux command:

ip address ip route

Tasks:

  1. Identify an active network interface.
  2. Record its IP address.
  3. Identify its subnet information.
  4. Identify the default gateway, if configured.
  5. Identify the DNS configuration where available.

Evidence: A sanitised configuration worksheet.

Exercise 02

Understand DNS Resolution

Objective: Observe how a domain name is resolved.

Windows or Linux command:

nslookup example.com

Tasks:

  1. Run the DNS lookup command.
  2. Identify the queried domain.
  3. Identify the DNS server shown in the result.
  4. Record the returned address information.
  5. Explain what the result establishes and what it does not establish.

Evidence: A DNS lookup analysis note.

Exercise 03

Inspect Network Connections

Objective: Understand active network connection information.

Windows command:

netstat -ano

Linux command:

ss -tunap

Tasks:

  1. Identify local addresses and ports.
  2. Identify remote addresses and ports.
  3. Observe the transport protocol.
  4. Identify connection states where available.
  5. Explain why a listening port is not automatically malicious.

Evidence: A sanitised network connection worksheet.

Exercise 04

Inspect a Packet Capture

Objective: Understand packet-level network information.

Use Wireshark with a sample packet capture supplied by your training environment or capture traffic from your own authorised device.

Tasks:

  1. Open the permitted packet capture.
  2. Identify source and destination addresses.
  3. Identify TCP and UDP traffic.
  4. Identify DNS requests where present.
  5. Inspect TCP handshake packets where present.
  6. Record your observations and limitations.

Evidence: A packet analysis worksheet with relevant screenshots.

Privacy requirement Do not publish captures containing passwords, personal information, session tokens or confidential communication. Use synthetic or sanitised captures for public submissions.
Exercise 05

Build a Network Protocol Reference Sheet

Objective: Build a quick reference for common protocols.

Tasks:

  1. Document at least ten common protocols.
  2. Describe the purpose of each protocol.
  3. Record commonly associated ports where applicable.
  4. Identify whether the protocol commonly uses TCP, UDP or both.
  5. Document one security monitoring consideration for each selected protocol.

Evidence: A documented protocol reference sheet.
